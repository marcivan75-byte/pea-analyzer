# V21.1 — Integration du module OR V1 dans le process global

## Statut

Le module `GOLD_V1.0_BASELINE_102` est integre au process global en mode **SHADOW / RESEARCH_ONLY**.

Il est autonome par rapport aux modules Actions PEA et ETF PEA. Son integration ne modifie aucun poids, seuil ou univers existant de ces deux modules.

## Process global

1. Acquisition des donnees et provenance PIT.
2. Construction des features propres a chaque module.
3. Scoring propre au module, avec ses ponderations propres.
4. Application des hard gates propres au module.
5. Production du comite propre au module.
6. Synthese globale sans reutilisation de ponderations entre classes d'actifs.

## Contrat Actions / ETF inchange

- Actions PEA : 1 829 instruments valides.
- ETF PEA : 102 instruments valides.
- Total PEA : 1 931 instruments.
- L'or n'entre pas dans ce nombre d'instruments PEA.
- Les ponderations Actions ne sont pas modifiees.
- Les ponderations ETF ne sont pas modifiees.
- T1/T2 restent exclusivement reserves au module Actions TCT.

## Contrat OR V1

- 102 criteres.
- 11 familles.
- score MT prioritaire.
- score CT de timing.
- `ENTRY_SCORE = 75 % MT + 25 % CT`.
- double vue XAU/USD et XAU/EUR.
- reponderation dynamique par regime avec plafond de +/-25 % puis renormalisation a 100 %.
- pas d'imputation neutre a 50 pour les donnees manquantes.
- publication obligatoire de la couverture de poids et du QDS_OR.

## Hard gates OR

1. `DATA_QUALITY`
2. `ANTI_LOOK_AHEAD`
3. `CROWDING`
4. `GEOPOLITICAL_CONFIRMATION`
5. `CORRELATION_DOUBLE_COUNTING`
6. `MACRO_CONFLICT`

QDS_OR :

- >=85 : decision de recherche avec confiance normale ;
- 75 a 84,99 : confiance reduite ;
- <75 : aucune decision exploitable.

Le gate anti-look-ahead est bloquant quel que soit le score.

## Donnees et PIT

Le registre specifique `config/V21.1_GOLD_SOURCE_REGISTRY.csv` separe les sources deja reutilisables du process des adaptateurs encore a materialiser pour l'or.

Pour toute observation exploitee :

`available_at <= decision_timestamp`

La date economique ou la periode de reference ne remplace jamais la date reelle de publication. Cette regle est notamment obligatoire pour COT, banques centrales, demande physique, macro et consensus.

## Gouvernance des poids

Les poids OR V1 constituent une baseline de calibration. Ils sont integres dans le code afin de pouvoir etre testes de maniere reproductible, mais ils ne sont pas declares optimaux.

Activation reelle interdite avant :

1. reconstruction historique PIT ;
2. backtest walk-forward ;
3. validation out-of-sample ;
4. holdout final reste gele pendant la calibration ;
5. audit des correlations et du double comptage ;
6. validation explicite de la version optimisee.

## Sortie du comite OR

Le runner publie au minimum :

- GOLD_SCORE_MT ;
- GOLD_SCORE_CT ;
- ENTRY_SCORE ;
- QDS_OR ;
- regime OR ;
- confidence ;
- decision MT ;
- couverture de poids MT/CT ;
- scores des 11 familles ;
- hard gates actifs ;
- `execution_allowed=false` tant que le backtest n'est pas valide.

En l'absence de snapshot live, le runner ne fabrique aucun score : MT et CT restent `null`, QDS_OR vaut 0 et la decision est bloquee par la qualite des donnees.

## Workflow

Le workflow `.github/workflows/V21.1_gold_v1_shadow.yml` est volontairement `workflow_dispatch` uniquement. Une simple modification du depot ne lance donc pas automatiquement le module.

Il execute :

1. validation statique du contrat 102 criteres ;
2. controles de sommes de poids MT/CT ;
3. tests de gouvernance ;
4. comite shadow ;
5. hard gates de sortie ;
6. publication d'un artefact de recherche.

## Etape suivante

Construire les adaptateurs de collecte OR manquants puis reconstruire l'historique PIT necessaire au backtest de calibration. La V1 ne passe en version active qu'apres validation statistique hors echantillon.
