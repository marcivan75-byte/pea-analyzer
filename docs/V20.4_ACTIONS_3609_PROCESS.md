# V20.4 GitOK — Process Actions PEA 3609

## Source canonique

Le fichier quotidien unique est `data/external/ACTIONS_PEA_3609_LATEST.xlsx`.
Il est alimenté par le script indépendant de 18:00. Aucune variante V1/V2/V3 de cette source n'est créée par le Comité.

Le fichier audité le 2026-08-08 contient 3609 actions et 146 colonnes, sans formule Excel. Toutes les colonnes source sont conservées dans la sortie du Comité.

## Contrôle d'identité obligatoire

Les identifiants du fichier source ne sont jamais acceptés aveuglément. L'audit initial montre seulement 316 ISIN sur 3609 avec checksum ISIN valide. Les données sont donc rattachées selon une cascade traçable :

1. ISIN valide et exact sur le master canonique : confiance 1.00.
2. Nom société normalisé exact sur le master canonique : confiance 0.98.
3. Ticker exact sur une source canonique : confiance 0.92.
4. Sinon : `UNVERIFIED_SOURCE`, confiance 0.35.

Une action non vérifiée peut être `STRUCTURAL_CANDIDATE`, mais ne peut pas devenir `BUY_CANDIDATE` ni recevoir un prix d'entrée actionnable.

## Utilisation des 146 critères

Aucune colonne source n'est supprimée. Les champs descriptifs servent à l'identité, à l'éligibilité, à la segmentation ou au contexte. Les champs quantitatifs alimentent les familles : qualité, valorisation, momentum, risque, catalyseurs/consensus, structure/liquidité, fiscalité, expectancy et rotation/secteur.

Les scores V10 et ses piliers restent utilisés, mais sont croisés avec les critères bruts afin d'éviter de dépendre d'un score opaque unique.

## Horizons décisionnels

- T0 : setup immédiat / attente.
- T1 : 1 à 4 semaines ; entrée, cible et invalidation uniquement si identité et données quotidiennes sont suffisamment fiables.
- T2 : 1 à 3 mois.
- T3 : 3 à 6 mois.
- T4 : 6 à 12 mois.
- T5 : 12 à 24 mois.

Trois scores indépendants sont calculés : `score_short_term`, `score_medium_term`, `score_long_term`.

## Analyse short

`short_thesis_score` mesure une thèse baissière à partir de momentum négatif, faiblesse fondamentale/valorisation, risque et positionnement short. Il s'agit exclusivement d'une information de recherche. Aucun ordre short, dérivé ou brokerage n'est autorisé par le workflow.

## Architecture de collecte

Le fichier de 18 h est la couche large 3609 et évite une collecte API exhaustive. Les API et OHLCV supplémentaires doivent être ciblés sur la shortlist issue du premier screening (ex. top 300 / seuil de score) : consensus, publications, analyst momentum, MarketBeat, OHLCV avancé, ATR, moyennes mobiles et autres signaux nécessaires au timing.

Cette architecture garde la collecte hors du chemin critique tout en permettant un T1 précis sur les dossiers réellement susceptibles d'être retenus.

## Sorties obligatoires

- `outputs/V20.4_GITOK_ACTIONS_3609_DECISIONS.csv` : 3609 lignes avec les 146 critères source + scores dérivés + identité + T0/T1/T2/T3/T4/T5 + short + décision.
- `outputs/audit/V20.4_ACTIONS_3609_AUDIT.json` : couverture identité, qualité et décisions.
- Les décisions ne peuvent utiliser que `RECOMMENDATION_ONLY` ou `RESEARCH_ONLY`; aucune exécution réelle.

## Quality Gates

- univers >= 3500 lignes ;
- nom société unique ;
- 146 colonnes source attendues pour la version courante ;
- conservation intégrale des colonnes source ;
- audit du taux d'ISIN valides ;
- audit de la couverture identité canonique ;
- aucun BUY sans identité de confiance >= 0.92 ;
- aucun prix T1 sans identité de confiance >= 0.92 ;
- aucun statut d'exécution live/order/broker.
