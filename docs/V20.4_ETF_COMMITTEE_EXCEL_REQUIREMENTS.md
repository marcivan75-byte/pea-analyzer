# V20.4 ETF PEA — Excel committee publication requirements

After every ETF PEA committee selection, publish an Excel workbook containing **only ETFs with `etf_266_score > 77`**.

## Mandatory workbook structure

### Sheet `ETF score >77`
- Row 1: weighting / scoring rule for each criterion.
- Row 2: column headers.
- One ETF per row, sorted by decreasing final score.
- Include every criterion used by the ETF 266 scoring engine and its observed value / assigned score.
- Include final score, structural score, technical adjustment, committee decision and execution guard.
- Include daily-match method and confidence.
- Include last price when reliable.
- Include an indicative entry zone and/or timing condition, explicitly outside the score.
- Include a concise text comment explaining why the ETF is selected.

### Sheet `Glossaire`
For each criterion: definition, weighting/rule, interpretation and role in the selection.

### Sheet `Métadonnées`
At minimum: GitHub run ID, universe size, threshold, number of selected ETFs, execution rule, and price/timing disclaimer.

## Mandatory criteria/rules to expose
- Score V9: 58% of structural base.
- Combined liquidity score: 12%.
- Replication score: 8%.
- Detailed ESG score: 5%.
- Availability score: 5% after normalization to /100.
- Sharpe: bounded bonus/malus (approximately 2×Sharpe, capped ±3 points).
- AUM thresholds: <15 M€ -12; <50 M€ -5; >=500 M€ +3.
- Spread thresholds: <=0.20% +3; >0.70% -6; >1.20% -12.
- TER thresholds: <=0.20% +2; >0.70% -5.
- SRRI >=6: -3.
- Tracking Error >0.60%: -4.
- Max drawdown below -40%: -4.
- ADV >=10 M€: +2.
- 3-month performance: technical contribution bounded ±4 using 0.20×Perf3m.
- 1-year performance: technical contribution bounded ±3 using 0.05×Perf1y.
- RSI14: 50-68 +2; >72 overbought penalty; <35 -3.
- MACD histogram: bounded technical contribution ±2, approximately 2×MACD histogram.
- Relative strength: bounded contribution ±2, approximately 0.08×relative strength.
- Positive reversal flag: timing/support indicator.
- Daily match method/confidence: data-confidence criterion; `NAME_FAMILY_PROXY` must never by itself create `BUY_CANDIDATE`.

## Entry-price/timing governance
- Entry guidance is **not part of the score**.
- Never invent an entry price when no sufficiently reliable daily price is available.
- If daily match is absent/insufficient: state `Attendre confirmation quotidienne`.
- If RSI >72: favor a 3-5% pullback and technical confirmation.
- If RSI is roughly 45-68 with positive reversal: allow staggered entry around current price / small pullback, subject to reliable identity matching.
- Family proxies require additional confirmation before execution-oriented interpretation.

## Safety
- Workbook remains decision support only.
- No live brokerage, order placement or real execution can be enabled.
