# V20.5 — Architecture décisionnelle en entonnoir

## Principe

Le moteur ne doit pas additionner indistinctement toutes les informations disponibles. Il doit réduire progressivement l'incertitude selon une chaîne **top-down puis bottom-up**. Chaque étage peut :

1. laisser passer le candidat ;
2. réduire sa confiance / son multiplicateur ;
3. imposer `REVIEW_ONLY` ;
4. bloquer un `BUY_CANDIDATE` ;
5. déclarer une donnée `N/A` sans fabriquer une valeur neutre.

Aucune donnée absente ne vaut automatiquement 50/100.

## Entonnoir obligatoire

### 1. Macroéconomie mondiale
- croissance / récession ;
- inflation globale ;
- courbe des taux ;
- chômage ;
- régime risque-on / risque-off ;
- matières premières pertinentes.

### 2. Inflation par pays / zone
- États-Unis : sources officielles / FRED ;
- zone euro et pays européens : Eurostat HICP courant ;
- contrôle de fraîcheur obligatoire ;
- les données anciennes sont `N/A`, jamais réutilisées comme si elles étaient actuelles.

### 3. Taux par pays / zone
- taux directeurs ;
- taux de marché courts / longs ;
- pente de courbe ;
- sens récent du mouvement.

### 4. Banque centrale et Fed
Séparer strictement :
- **politique actuelle** : taux effectivement en vigueur et communications officielles ;
- **biais futur de marché** : anticipation implicite issue des taux de marché ;
- ne jamais présenter une anticipation de marché comme une promesse de la Fed.

### 5. Actualité mondiale
Événements susceptibles de modifier le régime de risque : géopolitique, sanctions, guerre, crise, énergie, commerce, réglementation, stress financier, etc.

### 6. Actualité pays
Contexte économique, politique, fiscal, réglementaire et marché propre à l'exposition géographique de l'instrument.

### 7. Actualité sectorielle
Demande, prix, réglementation, innovation, consolidation, résultats sectoriels et risques propres au secteur.

### 8. Actualité instrument / société
Appliquée après un premier filtrage pour préserver l'effet d'entonnoir. Pour un ETF : actualité de l'indice, du thème, du fournisseur ou de la structure du fonds. Pour une Action : résultats, guidance, opérations capitalistiques, contentieux, changements de consensus, etc.

### 9. Sentiment de marché
- VIX ;
- Fear & Greed ;
- AAII ;
- autres mesures uniquement si leur source, fraîcheur et interprétation sont vérifiables.

Les extrêmes de sentiment servent principalement de modificateurs de risque / timing, pas de justification autonome d'achat.

## Branche Actions

### 10A. Fondamentaux société
Qualité, croissance, rentabilité, bilan, valorisation, cash-flow, consensus et révisions analystes.

### 11A. Technique / timing
Tendance, MACD, Bollinger, stochastic, volumes, force relative, retournements, breakout, volatilité et niveaux d'invalidation.

### 12A. Smart Money
Insiders, positions courtes publiées, flux institutionnels/tape lorsqu'ils sont réellement disponibles et validés.

## Branche ETF — univers canonique 102 uniquement

### 10B. Structure / fondamentaux ETF
- identité et ISIN validés ;
- AUM ;
- TER ;
- liquidité / volume / spread lorsqu'il est observable ;
- tracking error uniquement si couverture suffisante ;
- diversification observée ;
- Morningstar lorsque disponible ;
- risque / drawdown / volatilité ;
- **aucun traitement opérationnel du legacy 266**.

### 11B. Technique / timing ETF
Performances 1m/3m/6m/1a, force relative, MACD, RSI, RVOL, volatilité, drawdown et signaux de retournement.

### 12B. Smart Money ETF
Les flux ETF sont historisés par date. Tant que l'historique minimum n'est pas atteint, le module reste `PARTIAL` / `INSUFFICIENT_HISTORY` et ne crée aucun faux signal neutre ou positif.

## 13. Risk & execution gate

Dernier étage avant le comité :
- couverture de données ;
- identité ;
- liquidité / AUM ;
- contexte macro/news ;
- Smart Money négatif haute confiance ;
- invalidation technique ;
- statut `RESEARCH_ONLY`.

## Politique Smart Money

### Phase RC / validation
- `SHADOW_ONLY` ;
- aucun bonus positif dans le score de production ;
- un signal négatif de forte confiance peut uniquement dégrader/bloquer une recommandation positive ;
- état persistant entre les runs ;
- walk-forward empirique obligatoire.

### Activation positive ultérieure
Condition minimale :
- au moins 20 observations / 20 dates distinctes selon le contrat de calibration ;
- résultats walk-forward concluants ;
- calibration explicitement autorisée ;
- absence de dégradation des quality gates.

L'activation ne doit jamais être automatique sur la seule base du passage des tests structurels.

## Gouvernance des données manquantes

- pas de `50/100` fabriqué ;
- pondérations renormalisées sur preuves observées ;
- une composante trop peu couverte dans l'univers est désactivée uniformément pour éviter un avantage artificiel aux rares instruments renseignés ;
- la couverture effective est publiée avec chaque score.

## Univers ETF de référence

À compter de V20.4.3 / V20.5 :
- **102 ETF PEA validés** ;
- **266 non chargé, non scoré, non utilisé comme fallback** ;
- toute tentative de réintroduction du 266 doit faire échouer les quality gates.

## Sécurité

- `RESEARCH_ONLY` ;
- aucun ordre live ;
- aucune mutation positive Smart Money avant validation empirique ;
- chaque donnée macro/news/sentiment doit conserver sa provenance et sa fraîcheur.
